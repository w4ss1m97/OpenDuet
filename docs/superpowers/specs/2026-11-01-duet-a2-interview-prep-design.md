# Duet A2 — Interview prep (design)

Reviewed by the architect agent on 2026-11-01. Wassim decided: the LLM writes the sheet; calendar link = attendee
email, else one open mission whose company is in the title. The D-1 18:00 + H-1 reminders already exist (classify.ts).

## Decisions
1. Own table, one sheet per interview item (`item_id` UNIQUE); items/upsertTracked untouched.
2. Sheet = JSON `content {pitch, likelyQuestions[], questionsToAsk[]}`, zod-checked, URLs stripped, plain text in app.
3. Generated by a sweep after every intake (like relances): active interview items due within 72 h, mission open+active.
   3 attempts per sheet, 3 generations per run, 60 s timeout. Sweep failure is logged, never fails the intake.
4. Moved interview → no regeneration. New sheet only when the item's mission changes, or via the regenerate route.
5. Two interviews on one mission → two sheets.
6. Mission closed / item dismissed or done / no mission → nothing generated, existing sheet kept.
7. Calendar link: attendee/organizer email in an open active mission's contact_emails (exactly one), else exactly one
   open active mission named in the title (A1 `namesCompany`); else none. linkMission keeps an existing link.
   A contact match also advances the mission to `interview` (missions.advance, source 'calendar'-like hash
   `gcal:<id>`, matchedBy 'contact', forward-only); a title match only links, never moves the stage.
10. Sheets are read-only in the app (read + regenerate); no edit/dismiss route. Prompt-injection risk accepted with
    the mitigations above (fenced mails, contacts only, schema check, no URLs, no tools).
8. LLM: `createModelCompleter` (src/routing/model.ts) → `Complete` (triage.ts); optional `prep` dep in runIntake; add
   optional `maxTokens` (default 1024), prep uses 2048.
9. `calendar_list_events` already returns end, organizer, attendees (google-workspace-rest.ts:1172-1187).

## Batch 1 — schema
`src/db/schema/openduet-interview-preps.ts` (export from index): id, item_id→items cascade UNIQUE, owner_user_id→users
cascade, mission_id→missions cascade NOT NULL, status 'pending'|'ready'|'failed', content jsonb null, attempts int 0,
claimed_at, last_error (error name only), generated_at, created_at, updated_at.
CHECKs: status list; `status <> 'ready' OR content IS NOT NULL`; `attempts >= 0`. Index (owner, status).
Migration 0070 via `bun run db:generate --name openduet_interview_preps`; never hand-edit the journal; migrate dev + test.

## Batch 4 — intake
Calendar scanner returns `events`; after upserts, before advanceCursor, if deps.missions: matchEventMission vs open
active missions → store.linkMission(owner, 'gcal:'+id, m.id); failure fails the calendar scanner (as A1).
Optional dep `prep?: {store, complete, timeoutMs?}`; after the relance sweep, prepSweep in try/catch: ensurePending →
claim → mission + last 20 events → Gmail `from:(c…) OR to:(c…) newer_than:90d` max 5 → read first 3 → complete →
parsePrep → complete(); any throw → fail(). No contacts → mission + events only. Log `openduet-prep-error`, name only.
Wire in src/index.ts (~2320) with the same resolveApiKey as index.ts:1248.

## Batch 5 — routes, brief
items/routes.ts: GET /:id/prep (404 | status+content; the D-1 notification opens it), POST /:id/mission
{missionId|null} (mission checked via missions.get(owner) → 404; queues a sheet), POST /:id/prep/regenerate.
missions/routes.ts: GET /:id/preps. brief.ts: `interviews` for tomorrow (Paris) {itemId, title, dueAt, missionId|null,
prep}; loader in wiring.ts next to loadBriefMissions; failure → couldNotCheck "Entretiens".
