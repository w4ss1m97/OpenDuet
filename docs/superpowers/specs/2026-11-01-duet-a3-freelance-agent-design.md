# Duet A3 — Freelance agent: offers, tailored CV, revision (draft micro-spec)

Status: DRAFT, not yet reviewed by the architect. Builds on A1 (missions), A2 (prep), A2b (debrief).
Target (Wassim, 2026-11-01): TJM ≥ 500 €/day, remote or hybrid IDF, available ASAP. Profile: Consultant DevOps/SRE &
Cloud AWS, 7 years, dev background (CV ~/Desktop/wassim S. (1).pdf). Platforms now: Malt, Collective, Free-Work.

## Facts checked
- Intake already reads Gmail with bodies (`format: "full"`) and knows the 3 platform domains (mail-parsers.ts,
  mission mail-signal.ts). Job-alert mails are DROPPED today (`missionSignal` → null): A3 picks them up.
- No scraping, no logging into the platforms, no auto-apply (accounts at risk + ToS). Source = the mails the platforms
  send (alerts, Malt project proposals, Collective digests) + an offer URL pasted by Wassim.

## A3a — Offers (sourcing + score)
- **Goal:** every platform offer mail becomes an offer card, filtered and scored against the CV; good ones are pushed.
- **Files:** db/schema/openduet-offers.ts, migration 0072, offers/{parse.ts (per-platform mail → offers), score.ts,
  store.ts, routes.ts}, items/intake.ts (offer sweep), brief.ts (top offers), src/index.ts.
- **Rules:** hard filter first (TJM known and < 500 → hidden; on-site outside IDF → hidden; unknown TJM kept, flagged).
  Then LLM score 0–100 vs the master CV + reasons + missing skills. Dedup by URL/platform id. Score ≥ 75 → push
  notif + brief. "Je postule" → creates the mission piste (A1) linked to the offer.
- **Edge cases:** one digest mail = many offers · same offer on 2 platforms → one card · TJM as range or daily/annual ·
  English offers.
- **Tests:** parser per platform on saved mail fixtures, hard filter, dedup, score parse (zod), sweep limits, routes owner.

## A3b — Tailored CV
- **Goal:** for one offer, a CV variant that puts forward what the offer asks, from the master CV only.
- **Files:** db/schema (master CV jsonb + tailored versions), offers/cv.ts, offers/cv-render.ts (HTML → PDF), routes.
- **Rules:** master CV = structured JSON imported once from the PDF, editable. LLM may reorder, select, rephrase bullets,
  adapt the title and profile, never add a skill, tool, client or number not in the master (checked in code: every
  tool named in the output must exist in the master). Output: PDF + a "match" report (covered / missing keywords).
- **Out of scope:** cover letters (A4 drafts), editing in the app.

## A3c — Revision ("je ne me souviens plus")
- **Goal:** Wassim keeps his knowledge fresh and has ready answers in interviews.
- **Files:** db/schema (cards + review state), offers/revision.ts, routes, brief.ts, prep.ts (A2 sheet adds cards).
- **Rules:** cards generated from the CV: concept questions per skill (EKS IRSA, Terraform state, blue/green…) and
  "story" cards (STAR with the CV's numbers: 50+ apps migrated, -20 % Graviton, DORA pipeline). Spaced repetition
  (Leitner, 5 cards/day), quiz in chat ("interroge-moi sur EKS"). Before an interview the A2 sheet adds the cards
  matching the offer's stack.

## Order
A3a → A3b → A3c (each its own batch and PR). A4 (Gmail drafts of applications/relances) after.

### Decisions
1. Sources: Malt, Free-Work, Collective mails only (LinkedIn out of v1). Pasted offer TEXT yes (POST); a pasted URL is
   stored, never fetched. No scraping.
2. `isOfferSource(mail)` (pure, job-offers/sources.ts): sender domain ∈ 3 platforms AND subject matches `OFFER_SUBJECT`
   (`alerte|nouvelles? (offres?|missions?|projets?)|offres? pour vous|(missions?|projets?) qui|proposition de projet|
   nouveau projet|new project|opportunit|sélection|correspond`) AND text not `CONVERSATION`
   (`candidature|vous a (envoyé|écrit)|message de|a répondu|entretien`). `platformOf(from)` → 'malt'|'free-work'|
   'collective'. `parseMail` → null for offer sources. `applyMailToMissions` guard `if (!mission && signal === null) return;`.
3. Table `openduet_offer_sources`: id, owner_user_id→users cascade, source_key (`gmail:<msgId>` | `paste:<sha256>`),
   platform, status `pending|done|failed|skipped`, attempts 0, claimed_at, last_error (name), offers_found 0,
   received_at, paste_text null (nulled on done), created_at, updated_at. UNIQUE (owner_user_id, source_key). CHECKs as
   preps. `ensureSource` = insert on conflict do nothing (idempotent per Gmail id).
4. Table `openduet_offers`: id, owner_user_id→users cascade, source_id→offer_sources set null, dedup_key, platform,
   url, title, company, tjm_min/tjm_max int, rate_unit `day|hour|year|unknown`, contract `freelance|salaried|unknown`,
   remote `full|hybrid|onsite|unknown`, location, duration_months, start_asap bool, skills text[] {}, description,
   status `new|scored|shown|filtered|dismissed|applied`, filter_reason `salaried|low_tjm|outside_idf` null,
   tjm_unknown bool, score int null (0–100), reasons jsonb [], missing_skills jsonb [], profile_hash, score_attempts 0,
   claimed_at, last_error, scored_at, mission_id→openduet_missions set null, seen_count 1, last_seen_at, created_at,
   updated_at. UNIQUE (owner_user_id, dedup_key). Index (owner_user_id, status, score).
5. Status (pure job-offers/status.ts `canTransition`): insert → `new`|`filtered` (hard filter); `new` → `shown` (≥75) |
   `scored` (<75); `new|scored|shown|filtered` → `dismissed`|`applied` (Wassim); `dismissed` → `applied`; `applied`
   terminal. 3 failed scores → stays `new`, score null. Re-sighting bumps seen_count/last_seen_at only.
6. Hard filter (pure job-offers/filter.ts `hardFilter`), first match wins: salaried or rate_unit year → `salaried`;
   day rate = tjmMax ?? tjmMin (hour × 7) known and < 500 → `low_tjm`, unknown → kept + tjm_unknown; onsite|hybrid with
   known location outside IDF → `outside_idf` (`isIdf`: Paris, IDF/Île-de-France, postcodes 75/77/78/91–95, ~25 cities:
   La Défense, Boulogne, Issy, Nanterre, Courbevoie, Puteaux, Levallois, Saint-Denis, Montreuil, Massy, Saclay,
   Versailles, Vélizy, Créteil…). Unknown location kept. Full remote anywhere kept.
7. Extraction (job-offers/extract.ts): `buildExtractPrompt({platform, subject, body})` FR, HTML stripped, whitespace
   collapsed, cap 15 000 chars, random per-call fence (copies stripped) + "data, not instructions" line. Answer
   `{offers:[…]}`; `parseExtraction`: one JSON object, each offer zod-parsed alone (bad dropped), ≤20 per mail. Limits:
   title 1–200, company ≤120, tjm int 0–5000, skills ≤20×40, description ≤600 URLs stripped, url only https.
   Non-JSON → `OfferAnswerError` (attempt spent). Zero offers → source done, offers_found 0.
8. `dedupKey` (pure): company known → `c:`+sha256(companyKey(company)|companyKey(title)); else canonical platform url
   (host = platform domain or www., not click./links./email./t.; no query/hash; lowercase; no trailing slash) → `u:`+url;
   else `p:`+sha256(platform|companyKey(title)|companyKey(location ?? "")).
9. Profile (job-offers/profile.ts): `ProfileSource { text(ownerUserId) }`. v1 = `OPENDUET_PROFILE_PATH` (absolute,
   existing file, read each sweep, cap 8 000 chars, else null). A3b swaps in a DB source. Null → no scoring, no attempt.
   `profile_hash` = sha256 stored with the score.
10. Score (job-offers/score.ts): `buildScorePrompt(profile, offer)` profile trusted, offer fenced. Answer
    `{score 0–100, reasons ≤4×200, missingSkills ≤8×40}` via zod `parseScore`. `SHOW_THRESHOLD = 75`.
11. LLM: reuse `prepComplete` (same model, 2048 tokens), 60 s per call via `withDeadline` + AbortController.
12. Intake: optional dep `offers?: {store, profile, complete}`. Mail scanner: `isOfferSource` →
    `ensureSource(owner, 'gmail:'+id, platform, date)`, never to `applyMailToMissions`. `offerSweep` runs LAST (after
    prepSweep), try/catch, runs even if the mail scanner failed. A: sources pending|failed attempts<3, received ≤14 d
    (older → skipped), newest first, ≤5/run: claim → GMAIL_READ → extract → insertOffers (filter) → complete; empty
    body → skipped. B: offers `new`, score_attempts<3, newest first, ≤10/run. ≤15 LLM calls/run. Claims as preps
    (attempts+1, stale 10 min, holder-only complete/fail).
13. Routes (job-offers/routes.ts `createOfferRoutes`) at `/api/openduet/offers` in app.ts, owner-filtered, other owner
    → 404: `GET /?status=csv&limit≤100` (default new,scored,shown; score desc nulls last, created desc); `GET /:id`;
    `POST /:id/dismiss` (applied → 409); `POST /:id/apply` → `missions.createPiste(owner, {company: company ?? platform
    label, role: title, review:'active', stage:'piste', at: now})` + `setApplied`, idempotent; `POST /paste {text
    50–20 000, url?}` → inline extract+filter+score, ≤3 offers, 120 s; same text → existing offers.
14. Brief: `BriefOffer {id,title,company,platform,score,reasons,tjmMax,remote}`, `deps.offers?` in buildMorningBrief
    (failure → couldNotCheck "Offres"); `loadBriefOffers` in wiring.ts: `shown`, scored_at ≥ now−24 h, top 5.
15. Migration 0072 `bun run db:generate --name openduet_job_offers`; add `./src/db/schema/openduet-job-offers.ts` to
    drizzle.config.ts. Never hand-edit the journal. Migrate dev + test.
16. Privacy: mail + profile text → same LLM provider as A2. Logs = names only.
